# 1. Зачем нужен Work A

Work A использовалась не для проверки уже готового инструмента, а как первый **development case**, столкновение кандидатной матрицы с реальным учебным продуктом.

Первый проход показал недостаточность общей шкалы `0 / 1 / 2`: наличие элемента, наличие связи, корректность связи, согласованность и предъявленность основания смешивались в одном коде. Из этого stress-test возникли v0.7 → v0.7.1 → pre-freeze revision → нормализованная v0.7.2.

Следовательно, Work A нельзя использовать как независимое подтверждение различительной способности v0.7.2. Её функции:

- development case;
- worked example;
- источник issue log;
- проверка того, что новые правила дают более локализованное описание модели.

# 4. Frozen course-requirement provenance для Work A

Полная таблица требований вынесена в `ARTICLE1_CORPUS_A_REQUIREMENTS.md` и применяется ко всем шести работам.

Для Work A наблюдались четыре типа сочетаний:

- `Т + Н1`: большинство обучавшихся структур (ресурсы / процессы, M0, M1, финансирование, риски, критерий) присутствуют;
- `Т + Н0`: ценность как изменение состояния пользователя не удержана;
- `t⁰ + Н1`: граница системы предъявлена сверх явного требования;
- `t⁰ + Н0`: project increment и альтернатива отсутствуют и при этом явно не требовались курсом.

Это важное ограничение интерпретации: отсутствие строки 8/14 в Work A нельзя автоматически считать доказательством общей когнитивной трудности.

# 5. Итоговый диагностический профиль

> **Work A содержит больше интеграции, чем показывала старая шкала. M0 и часть M1 количественно связаны, финансирование сведено, один критерий арифметически прослеживается. Центральный разрыв концентрируется на стыке `проект / компания / время`: проект не отделён от траектории всей компании, механизм воздействия не связывает действия с отдельными величинами, baseline без проекта отсутствует, а часть приписываемого проекту эффекта датирована раньше запуска. Основания ключевых целевых величин в презентации в основном не предъявлены.**

Это описание существенно точнее общего суждения «финансовая часть плохо обоснована»: инструмент локализует **тип и место разрыва**.

# 6. Что изменилось благодаря development case

Work A привела к следующим изменениям инструмента до freeze:

- отказ от единой шкалы `0/1/2`;
- разделение наличия, интеграции, корректности, согласованности и предъявленности основания;
- введение project increment `Δ`;
- разделение временной размерности и временной последовательности;
- разделение критерия и альтернативы;
- provenance требования курса;
- `НД` и правило короткой проверки;
- реестр противоречий;
- `CORE + optional domain adapters`;
- универсальный протокол проверки критерия вместо финансового glossary в core.

Коды Work A после v0.7.1/pre-freeze уточнений **не переписывались ради улучшения результата**; изменились отдельные дефициты и интерпретация.

# 7. Ограничения пилота

- один кодировщик;
- инструмент и пилот развивались совместно;
- доступна только презентация, без Excel / записи защиты;
- часть величин читается с графиков;
- артефакт не позволяет делать выводы о внутреннем процессе рассуждения отдельных учеников;
- реконструированный «правильный» NPV / payback не используется как доказанный факт без исходной модели.

Следовательно, Work A демонстрирует **полезность разработки**, но не её межэкспертную воспроизводимость и не novelty level 2.
