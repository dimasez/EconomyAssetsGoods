# 1. Единица анализа и граница вывода

Единица анализа — **итоговый учебный продукт команды / доступный пакет материалов**: презентация, письменный бизнес-план, Excel, запись защиты и иные явно включённые источники.

> **Наблюдаемый след — элемент или отношение в учебном продукте, совместимое с выполнением соответствующей когнитивной операции и позволяющее кодировать её проявление в артефакте, но не доказывающее выполнение операции конкретным учащимся.**

След мог возникнуть благодаря ученику, команде, преподавателю, шаблону, ИИ или внешнему источнику.

Допустимо: «в презентации основание не предъявлено».

Недопустимо: «ученик не умеет обосновывать».

# 2. Измерения

## Н — наличие

Вопрос: **есть ли элемент?**

Значения: `1 / 0 / НД`.

- `1` — критерий строки выполнен на минимальном уровне наличия;
- `0` — источник читается, но элемента нет;
- `НД` — по доступному пакету решить нельзя.

Если `Н = 0`, остальные измерения строки обычно не применяются (`—`). Исключение: в строке 8 дефицит `Δ1` может давать `К−` даже при `Н = 0`, если результат всей системы явно выдан за эффект проекта.

## И — интеграция / целостность

Вопрос: **связан ли элемент с другими частями модели?**

- `0` — элемента достаточно для наличия, но связи нет;
- `1` — связь явно названа словами, стрелкой или структурой рассуждения;
- `2` — хотя бы одна связь данного типа прослеживается по величинам / расчёту;
- `НД` — данных недостаточно.

Операционная конвенция Corpus A: `И = 2`, если существует хотя бы одна полностью прослеживаемая связь требуемого типа. Остальные слабые места фиксируются отдельными дефицитами.

## О — предъявленность основания

Вопрос: **показано ли в данном источнике, откуда взялось число, предпосылка или утверждение?**

Значения: `+ / − / НД`.

### Опорное утверждение строки

**Опорным утверждением** считается число, предпосылка или содержательное утверждение, которое используется как свидетельство наличия / связи в данной строке, входит в расчёт другой величины, обосновывает заявленное изменение, M0/M1, проектный эффект или критерий решения.

Правило агрегирования `О`:

- `О+` — основание предъявлено **для всех опорных утверждений**, используемых как свидетельство по данной строке;
- `О−` — хотя бы для одного опорного утверждения основание в доступном источнике не предъявлено;
- `О = НД` — по доступному пакету нельзя определить, предъявлено ли основание для одного или нескольких опорных утверждений.

`О−` не означает, что основания не существует. Оно означает только: **основание не предъявлено в доступном источнике**.

При расширении пакета источников код `О` может измениться без изменения самого проекта.

## К — корректность

Вопрос: **допустима ли связь с точки зрения экономического содержания и онтологии объекта?**

Значения: `+ / − / НД`.

`К−` выводится из зарегистрированного дефицита класса `недоп`.

## С — согласованность

Вопрос: **не противоречат ли друг другу разные части продукта?**

Значения: `+ / − / НД`.

**С — сквозное измерение.** Оно не обязано быть заранее перечислено в столбце «Измерения» каждой строки.

Правило:

- `С−` присваивается любой строке, чьи элементы / величины затронуты установленным противоречием типа `Р` из реестра;
- `С+` — если релевантные элементы строки проверены по продукту и установленных противоречий нет;
- `С = НД` — если проверять нечего или источник не позволяет проверить согласованность.

Запись типа `RECON` («не воспроизводится / требует допущений исследователя») сама по себе `С−` не создаёт.

# 3. Классы дефицитов и пространство кодов

- `отс` — отсутствие элемента;
- `несв` — элемент есть, но требуемая связь не построена;
- `недоп` — связь экономически / онтологически недопустима;
- `непр` — основание не предъявлено.

Чтобы независимый кодировщик не путал измерения, дефициты и записи реестра, v0.7.3 использует непересекающиеся обозначения:

- `С+ / С− / С=НД` — **только измерение согласованности**;
- `ЭС1–ЭС4` — дефициты строки 4 «экономические сущности»;
- `ВД1–ВД3` — дефициты строки 5 «временная размерность»;
- `РП1–РП2` — дефициты строки 3 «ресурсы и процессы»;
- `REG-01`, `REG-02`… — идентификаторы записей реестра противоречий;
- `RECON` — тип записи реестра для исследовательской реконструкции / невоспроизводимости без допущения.

Один **тип дефекта** фиксируется один раз в наиболее точной строке.

Приоритеты:

- компания вместо проекта → строка 8;
- смещённая база M0/M1 → строка 9;
- эффект раньше проектного действия → строка 10;
- подмена экономической сущности → строка 4;
- разные значения одной величины в разных местах → реестр противоречий.

Одно свидетельство может поддерживать несколько **концептуально разных** дефектов. Тогда записи получают отметку `общее свидетельство` и не считаются независимыми наблюдениями.

# 4. Процедура кодирования

1. Заполнить карточку: версия матрицы, кодировщик, пакет источников, нечитаемые места.
2. Взять замороженную таблицу требований курса из `ARTICLE1_CORPUS_A_REQUIREMENTS.md`.
3. Прочитать продукт целиком без кодирования; пронумеровать страницы / слайды.
4. Заполнить реестр противоречий по опорным величинам.
5. Пройти строки 1–14 в порядке: `Н → И → О → дефициты`.
6. Для каждого кода записать источник, номер страницы и короткое свидетельство.
7. Вывести `К` из дефицитов `недоп`; вывести `С` из реестра.
8. Составить профиль из 3–5 предложений: что в модели связано, где разрывы и какого они типа.
9. Не присваивать интегральный балл работе и не делать выводов о способностях учащихся / эффективности курса.
10. Любая новая трудность инструмента идёт в Issue Log; правила Corpus A не меняются.

# 5. Общие операционные правила

### 5.1. `0` или `НД`

`0` — доступный источник читается и элемента нет.

`НД` — нужная часть нечитаема либо решение требует сведений вне доступного пакета.

### 5.2. Короткая проверка

Кодировщик может выполнить не более **двух арифметических действий** над явно показанными числами без допущений о методе. Это операционная конвенция, а не свойство экономической модели.

Более длинная реконструкция записывается как тип `RECON` и не используется сама по себе для отрицательного кода корректности или согласованности.

### 5.3. Соседство ≠ связь

Соседние блоки канвы, соседние слайды или расположенные рядом числа не считаются связью.

Связь требует хотя бы одного из признаков:

- причинно / функционально связывающего текста;
- стрелки / явной схемы;
- формулы;
- прослеживаемого расчёта.

### 5.4. И и О — разные свойства

Кодировщик может установить `И = 2` короткой проверкой. `О+` требует, чтобы основания всех опорных утверждений строки были предъявлены самим доступным источником; исследовательская реконструкция основания не превращает `О−` в `О+`.

### 5.5. Не исправлять работу

Исследователь фиксирует предъявленную модель. Он не достраивает за участников «правильный» проект и не заменяет отсутствующую связь собственным объяснением.

# 6. Реестр противоречий

Для Corpus A всегда проверяются, если присутствуют:

- выручка по годам;
- число клиентов / пользователей;
- чек / цена;
- прибыль, EBITDA, денежный поток;
- инвестиции / потребность в капитале;
- заявленный критерий / срок возврата;
- темпы изменения;
- даты этапов и эффектов;
- состав сегментов / клиентов.

Это **операционно выбранный список под жанр Corpus A**, а не универсальный core. Перед cross-domain freeze список должен задаваться функционально: изменяемые величины + величины критерия + даты + состав ключевых групп.

Идентификаторы записей: `REG-01`, `REG-02`…

Типы записей:

- `Р-число` — одна величина имеет разные значения;
- `Р-дата` — одно событие имеет несовместимые даты;
- `Р-состав` — взаимоисключающие описания состава одного объекта;
- `RECON` — показатель не воспроизводится короткой проверкой или воспроизводится только после исследовательского допущения.

Статус `установлено`: противоречие сохраняется при любом разумном прочтении подписей.

Статус `возможно`: период / определение неясны или расхождение может быть следствием точности чтения графика.

### Чтение графика

Операционная конвенция: значение читается с точностью `± 1/2` шага сетки оси. Если другое явно указанное число выходит за этот интервал — противоречие может быть признано установленным. Без сетки / подписей — только `возможно`.

# 7. Операциональные определения по строкам

## 1. Уровень и граница системы

В модели могут одновременно присутствовать целевая, использующая, обеспечивающая системы и окружение, а также разные уровни холархии. Само наличие нескольких систем не является ошибкой.

**Н:**
- `Н1` — названа целевая система и достаточно ясно очерчено, что к ней относится;
- `Н0 / Г0` — целевая система не определена.

**К:**
- `Г1 — недоп`: величина одной системы приписана другой без явного перехода;
- `Г2 — недоп`: сложены / напрямую сопоставлены величины разных систем или уровней без модели перехода.

Не дефицит: эффект для клиента / города показан отдельно и механизм перехода между системами назван.

## 2. Ценность для пользователя / использующей системы

Ценность кодируется как изменение состояния / деятельности использующей системы, а не как перечень свойств продукта.

**Н:**
- `Н1` — названа использующая система / группа и то, что у неё меняется;
- `Н0 / Ц1` — присутствуют только свойства продукта, преимущества или лозунги.

**И:**
- `И0` — изменение пользователя не связано с экономическим эффектом;
- `И1` — механизм экономического эффекта назван словами;
- `И2` — хотя бы одна связь `изменение состояния → экономический эффект` прослеживается количественно.

Экономический эффект может быть выручкой, снижением затрат, высвобождением времени / мощности, снижением риска, предотвращённым ущербом и др.; он **не сводится к платежу / доходу**.

Дефициты:
- `Ц2 — несв`: ценность не связана с экономическим эффектом;
- `Ц3 — непр`: опорная предпосылка о спросе / эффекте не имеет предъявленного основания.

## 3. Ресурсы и процессы

**Н1:** присутствуют хотя бы один ресурс и один процесс.

**И:**
- `0 / РП1` — параллельные перечни;
- `1` — ресурс связан с процессом и порождаемой экономической величиной словами;
- `2` — хотя бы одна величина выводится из ресурсов / процесса расчётом.

`РП2 — несв`: затраты / ограничения / потребность в ресурсе не связаны с названными ресурсами и процессами.

## 4. Различение экономических сущностей

Проверяется отсутствие подмены сущностей. Типовые, но не исчерпывающие пары:

- выручка ≠ прибыль;
- прибыль ≠ EBITDA ≠ денежный поток;
- цена ≠ ценность;
- относительный показатель ≠ его база.

Коды дефицитов:
- `ЭС1 — недоп`: выручка ↔ прибыль;
- `ЭС2 — недоп`: прибыль ↔ EBITDA ↔ денежный поток;
- `ЭС3 — недоп`: цена ↔ ценность;
- `ЭС4 — непр`: у опорного относительного показателя не предъявлена база и она не устанавливается короткой проверкой.

## 5. Временная размерность

Различаются:

- запас на момент ↔ поток за период;
- разовое ↔ регулярное;
- накопленное ↔ периодическое.

Дефициты:
- `ВД1 — недоп`: разовое смешано с регулярным;
- `ВД2 — недоп`: запас подан как поток или наоборот;
- `ВД3 — недоп`: величины разных временных размерностей сложены / сопоставлены без оговорки.

## 6. Текущее состояние M0

M0 определяется функционально: это текущее состояние **тех элементов, изменение которых затем заявляется**.

**Н:**
- `Н1` — хотя бы для одного изменяемого элемента задано текущее состояние числом или структурно;
- `Н0 / М0-0` — база отсутствует для всех заявленных изменений.

**И:**
- `0 / М0-1` — величины существуют по отдельности;
- `1` — связь названа;
- `2` — хотя бы одна итоговая величина выводится из предъявленных составляющих.

`М0-2 — непр`: основание / вывод опорной величины не предъявлен.

Если работа акцентирована на текущем состоянии и проектное изменение практически не предъявляется, это отмечается в профиле как **акцент работы, а не дефект сам по себе**.

## 7. Механизм проектного изменения

Требуемая цепочка:

`действие проекта → изменяемый элемент системы → изменяемая величина / состояние`.

**Н1:** действия проекта названы.

**И:**
- `0 / П1` — список действий без изменяемых величин;
- `1 / П2` — изменяемые величины названы, но действие не связано со своей величиной;
- `2` — хотя бы для одного опорного действия цепочка прослеживается.

`П3 — непр`: размер опорного заявленного изменения не имеет предъявленного основания.

## 8. Проектное приращение

Различаются:

1. состояние системы;
2. baseline «без проекта»;
3. проектное воздействие;
4. `Δ_project`.

**Н:**
- `Н1` — показан baseline либо эффект явно помечен как дополнительный к продолжению M0;
- `Н0 / Δ0` — вопрос «что произошло бы без проекта?» не поставлен.

`Δ1 — недоп`: полный результат компании / системы предъявлен как результат проекта или непосредственно положен в основу критерия проекта.

`К = НД`, если по подписям нельзя понять, полная это величина или приращение.

## 9. Целевое состояние M1

M1 вправе содержать новые продукты, активы, процессы, каналы, источники эффектов и статьи затрат. Требуется не идентичный набор переменных, а **сопоставимая база там, где заявляется изменение**.

**Н1:** целевые величины / состояния заданы с горизонтом.

**И:**
- `0` — ни для одного изменения нет сопоставимой базы;
- `1` — база есть для части изменений;
- `2` — хотя бы одна величина M1 прослеживается от сопоставимой M0 через заявленное изменение.

Дефициты:
- `М1-1 — несв`: для конкретного изменения нет сопоставимой базы M0;
- `М1-2 — недоп`: рост отсчитан от плана / иной смещённой базы при наличии фактической M0;
- `М1-3 — непр`: опорное целевое число без предъявленного основания;
- `М1-4 — несв`: новый элемент M1 не имеет названного происхождения из проекта.

## 10. Временная последовательность

Кодируется только если продукт датирует и действия, и эффекты; иначе `К = НД`.

- `Т1 — недоп`: приписываемый проекту эффект стоит раньше запуска действия;
- `Т2 — недоп`: положительная отдача проекта появляется раньше необходимого вложения / ресурса.

## 11. Финансирование / ресурсное обеспечение

Строка не сводится к внешнему инвестору. Проверяется связь:

`потребность в ресурсе / капитале → источник → условия / обязательства / ограничения`.

**Н1:** названа потребность и хотя бы один источник.

**И:**
- `0 / Ф1` — потребность не разложена и не связана с направлениями / источниками;
- `1` — есть связь либо с направлениями использования, либо с источниками;
- `2` — показаны направления и источники и их величины согласуются.

`Ф2 — отс/несв по контексту`: не названы существенные условия источника — стоимость, доля, возврат, срок, ограничение, обязательство и т.п., когда такие условия релевантны.

## 12. Предпосылки и риски

**Н1:** названы риски или ключевые предпосылки.

**И:**
- `0 / Рс1` — только категории / общие слова;
- `1` — риск связан с конкретной предпосылкой / величиной словами;
- `2` — влияние показано сценарием / чувствительностью / числом.

`Рс2 — отс`: нет сценариев или вариации значимой предпосылки.

Сценарии внешней среды кодируются здесь, а не как альтернатива действия в строке 14.

## 13. Критерий решения

Проверяется универсальным протоколом, а не финансовым справочником.

**Н1:** назван хотя бы один показатель / условие принятия решения, денежный или неденежный.

**И:**
- `0` — значение дано без входящих величин;
- `1 / Кр1` — величины названы, но значение не прослеживается;
- `2` — хотя бы один критерий прослеживается из предъявленных величин короткой проверкой.

**О:** применяется глобальное правило всех опорных утверждений строки из раздела 2.

- `О+` — для всех опорных входящих величин / параметров / нормативов / коэффициентов, используемых как свидетельство критерия, основание предъявлено;
- `О− / Кр2` — хотя бы для одного опорного элемента основание не предъявлено;
- `О = НД` — статус основания нельзя определить по доступному пакету.

**К:**
- `К− / Кр3` — входящие величины не соответствуют заявленному смыслу критерия.

`Кр4 — непр`: не определено, что именно оценивает критерий или за какой период.

Если объект назван, но выбран неверно (например, компания вместо проектного приращения), основной дефект кодируется в строке 8, а в строке 13 ставится ссылка.

### Девять вопросов к критерию

1. Что оценивается?
2. К чьей системе относится показатель?
3. Что показатель означает?
4. Какие величины входят?
5. Какой момент / период?
6. Соответствуют ли величины смыслу?
7. Прослеживается ли получение значения?
8. Предъявлены ли предпосылки / параметры?
9. С чем сравнивается результат?

Три слоя: **семантика → онтология → расчётная прослеживаемость**.

> **Воспроизводимость расчёта ≠ экономическая корректность.**

Техническая правильность специальной финансовой / инженерной формулы не является задачей CORE и при необходимости проверяется domain-specific adapter.

## 14. Альтернатива

Альтернатива — **иной вариант действия**, а не параметр расчёта и не сценарий среды.

**Н1:** названо хотя бы одно: ничего не менять; другой проект; другое использование капитала / ресурса; другой вариант реализации.

`А0 — отс`: альтернативный вариант действия не назван.

**И:**
- `0 / А1` — альтернатива названа, но не сопоставлена;
- `1` — сопоставлена словами;
- `2` — сопоставлена по тому же критерию количественно.

Не являются альтернативой сами по себе:

- ставка дисконтирования;
- внешний оптимистичный / кризисный сценарий;
- предложения конкурентов.

# 8. Provenance / происхождение требования

Разводятся два вопроса.

### Слой 1 — почему операция нужна

- `Пн` — смысл понятия;
- `Мд` — устройство модели;
- `Пр` — дисциплинарная / профессиональная практика;
- `Фм` — форма представления.

Метки могут пересекаться.

### Слой 2 — требовал ли её курс

- `Т` — требовалась явно;
- `t⁰` — явное требование в документах курса отсутствует;
- `Т?` — документация даёт близкое требование, но не позволяет уверенно считать данную операцию прямо заданной.

Таблица для Corpus A заморожена отдельно: `ARTICLE1_CORPUS_A_REQUIREMENTS.md`.

Presence элемента не означает самостоятельного порождения операции участниками: provenance не смешивается с качеством исполнения.
