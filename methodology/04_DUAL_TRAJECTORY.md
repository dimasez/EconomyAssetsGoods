# DUAL TRAJECTORY — v0.1

> Тема: согласование предметной траектории и траектории когнитивных операций.  
> Статус: **рабочая каноническая версия v0.1**  
> Дата: **2026-10-25**

---

## 1. Исходная идея

В ходе разработки семинара №6 возникла визуальная конструкция «две параллельные архитектуры».

Первая линия описывала предмет бизнеса:

`миссия и ценности → бизнес-модель → 9 блоков → внутренние различения → конкретные сущности → метрики → решения`

Вторая — действия мышления:

`реальность → различение → понятие → модель → измерение → умозаключение → решение → действие → результат → обратная связь`

Red Team справедливо указал, что прямые вертикальные соответствия вида `бизнес-модель ↔ модель` или `метрики ↔ измерение` являются слишком номинальными. Поэтому v0.1 уточняет конструкцию.

---

## 2. Новая формулировка

Вместо двух «архитектур» в строгом смысле используем:

> **две согласуемые траектории — предметную и операциональную.**

Предметная траектория показывает:

> **что меняется в представлении объекта.**

Операциональная траектория показывает:

> **какое интеллектуальное действие требуется для такого перехода.**

Связь между ними задаётся не сходством слов, а **матрицей переходов**.

---

## 3. Предметная траектория

Предварительная версия для бизнес-образования:

`задача → граница системы → миссия / ценности → стратегия → бизнес-модель → аспекты модели → типы сущностей → конкретные сущности → характеристики → конструкты → показатели → данные → выводы → решения → действия → результаты`

Важно:

- эта траектория не является универсальной линейной онтологией бизнеса;
- отдельные звенья могут пропускаться или возвращаться назад;
- она используется как **карта возможных переходов** для проектирования обучения.

---

## 4. Операциональная траектория

Соответствующий рабочий набор операций:

`постановка задачи → проведение границы → различение → понятийная фиксация → выбор критерия → моделирование → выделение аспекта → классификация → конкретизация → декомпозиция → атрибуция → операционализация → измерение → интерпретация → абдукция / умозаключение → выбор → действие → оценивание → проверка → рефлексия`

Это не психологическая последовательность «как человек всегда думает». Это язык проектировщика обучения.

---

## 5. Принцип согласования

Главная рабочая гипотеза:

> **Каждый значимый переход в предметной модели должен требовать определённой, называемой и проверяемой операции.**

Примеры:

| Предметный переход | Требуемая операция |
|---|---|
| система → части | декомпозиция |
| род → виды | классификация |
| класс → объект | конкретизация |
| объект → свойство | атрибуция |
| конструкт → индикатор | операционализация |
| данные → вывод | умозаключение |
| вывод + цель → решение | выбор |
| результат → модель | проверка / рефлексия |

Таким образом, курс проектируется не только как последовательность тем, но и как **последовательность интеллектуальных действий над предметным содержанием**.

---

## 6. Почему это важно для курса

Традиционная организация:

> тема → определение → пример → упражнение.

Предлагаемая организация:

> **предметная проблема → требуемая операция → модель → задача на перенос → рефлексия.**

Тема при этом становится не конечной целью, а **средой тренировки операции**.

Пример:

«Активы» — не только содержание о видах активов.

На материале активов можно тренировать:

- объект ↔ экономический статус;
- ресурс ↔ актив;
- род–вид;
- класс–экземпляр;
- статика ↔ динамика;
- финансовое значение ↔ реальный объект;
- частичный ответ ↔ собранная модель.

---

## 7. Не две параллельные линии, а система с петлями

Строгая версия должна учитывать обратные связи.

Рабочий цикл:

`задача субъекта → модель предмета → операционализация → данные → вывод → решение → действие → результат`

Далее:

### Одинарная петля

`результат → корректировка решения / действия`

### Двойная петля

`результат → пересмотр границы / различений / понятий / модели`

Следовательно, «две траектории» нужны прежде всего для анализа **внутри модельного цикла**, а не как две независимые прямые.

---

## 8. Роль субъекта

Red Team указал на отсутствие субъекта в ранней версии. Исправление принято.

Модель не строится «сама из реальности».

Всегда есть:

- субъект;
- задача;
- контекст;
- выбранная граница;
- предварительные понятия;
- критерии релевантности.

Поэтому рабочая входная формула:

`субъект + задача + ситуация → граница → различения → модель`

Реальность не исчезает: она остаётся источником ограничений, данных и обратной связи.

---

## 9. Предметная архитектура и когнитивная архитектура статьи

Научная статья №1 анализирует учебные артефакты и кодирует наблюдаемые следы операций.

Следовательно, появляется третий слой:

`предметная траектория ↔ когнитивная операция ↔ наблюдаемый след`

См. [`02_SUBJECT_OPERATION_TRACE.md`](02_SUBJECT_OPERATION_TRACE.md).

Это делает «двойную траекторию» фактически частью более широкой трёхслойной архитектуры.

---

## 10. Методический цикл

Курс можно проектировать по следующему циклу:

1. выбрать предметный переход;
2. определить требуемую операцию;
3. создать задачу, в которой операция необходима;
4. определить ожидаемый артефакт;
5. определить наблюдаемый след;
6. выполнить задание;
7. получить обратную связь;
8. проверить перенос на новую область;
9. скорректировать задание или модель операции.

Это связывает instructional design и исследование в единую систему.

---

## 11. Дидактический и исследовательский языки нужно разделять

Для преподавателя / исследователя допустимы:

- тип отношения;
- операция;
- критерий;
- типичная ошибка;
- наблюдаемый след;
- перенос.

Для студента не всегда нужно предъявлять всю метатеорию заранее.

Педагогический принцип:

> **сначала интеллектуальное действие, затем короткая рефлексия и называние операции.**

Это снижает риск когнитивной перегрузки и соответствует исходной логике курса: понятие должно «прорасти» через действие.

---

## 12. Сильная формулировка текущей гипотезы

> **Освоение предметной модели может быть организовано так, чтобы её структурные переходы выступали носителями воспроизводимых когнитивных операций.**

Более строгая версия для исследования:

> **Если учебная последовательность явно связывает тип предметного перехода с соответствующей когнитивной операцией и критерием корректности, учащиеся должны лучше переносить эту операцию на новые предметные ситуации, чем при обучении только содержанию модели.**

---

## 13. Что здесь может быть авторским вкладом

Не являются новыми сами по себе:

- моделирование;
- классификация;
- декомпозиция;
- BMC;
- обратная связь;
- обучение через деятельность.

Потенциальный вклад проекта:

> **согласованное проектирование предметного перехода, когнитивной операции и наблюдаемого следа с использованием экономических моделей как среды обучения.**

Эта формулировка должна проверяться эмпирически и не использоваться как утверждение о доказанной новизне до исследования.

---

## 14. Критерий развития к v0.2

Траектория должна быть проверена не только на Business Model Canvas, но минимум на:

- логике;
- активах;
- балансовой модели;
- оборачиваемости;
- системной модели;
- метриках;
- BPMN / процессах;
- проектах.

Если для каждого слоя удаётся задать устойчивые переходы, операции, критерии и переносные задания, конструкция становится архитектурой всего курса.
