# 1. Место в исследовательской архитектуре

Статья №1 различает три продукта:

1. **Архитектура когнитивных операций** — теория.
2. **Протокол реконструкции** — метод перехода от структуры экономического содержания к операциям и наблюдаемым следам.
3. **Кодировочная матрица** — инструмент анализа учебных артефактов.

`теория → протокол реконструкции → coding matrix → учебный продукт → профиль следов и дефицитов → проверка воспроизводимости`

Матрица не является психологическим тестом, рейтинговой рубрикой или финансовым чек-листом.

# 2. Что кодируется

Единица анализа — **итоговый учебный продукт команды / доступный пакет материалов**.

> **Наблюдаемый след — элемент или отношение в учебном продукте, совместимое с выполнением соответствующей когнитивной операции и позволяющее кодировать её проявление в артефакте, но не доказывающее выполнение операции конкретным учащимся.**

След операции в артефакте ≠ доказательство внутреннего мыслительного акта.

# 3. Измерения

| Код | Свойство | Вопрос | Значения |
|---|---|---|---|
| Н | наличие | есть ли элемент? | `1 / 0 / НД` |
| И | интеграция / целостность | связан ли элемент с другими частями модели? | `0 / 1 / 2 / НД` |
| О | предъявленность основания | показано ли в данном источнике основание опорных утверждений строки? | `+ / − / НД` |
| К | корректность | допустима ли связь экономически / онтологически? | `+ / − / НД` |
| С | согласованность | не противоречат ли части продукта друг другу? | `+ / − / НД` |

`И=0` — связи нет; `И=1` — связь названа; `И=2` — хотя бы одна связь данного типа прослеживается по величинам / расчёту.

### Правило О

Опорное утверждение — число, предпосылка или содержательное утверждение, используемое как свидетельство по данной строке либо как вход в M0/M1, проектный эффект или критерий.

- `О+` — основание предъявлено для **всех** опорных утверждений строки;
- `О−` — хотя бы для одного опорного утверждения основание не предъявлено;
- `О=НД` — по доступному пакету статус основания определить нельзя.

### Правило С

**С — сквозное измерение.** Оно присваивается любой строке, элементы которой затронуты реестром противоречий:

- `С−` — строку затрагивает установленное противоречие типа `Р`;
- `С+` — релевантные элементы проверены и установленных противоречий нет;
- `С=НД` — проверка невозможна / нерелевантна.

Запись типа `RECON` (исследовательская реконструкция / не воспроизводится без допущения) сама по себе `С−` не создаёт.

Если `Н=0`, остальные измерения строки не применяются, кроме явно видимой недопустимости строки 8 (`Δ1`).

### Пространство обозначений v0.7.3

- `С+ / С− / С=НД` — только измерение согласованности;
- `ЭС1–ЭС4` — дефициты различения экономических сущностей;
- `ВД1–ВД3` — дефициты временной размерности;
- `РП1–РП2` — дефициты ресурсов и процессов;
- `REG-XX` — идентификаторы записей реестра;
- `RECON` — тип записи реестра для исследовательской реконструкции.

# 4. CORE + domain-specific adapters

> **CORE coding matrix + optional domain-specific adapters**

CORE описывает инвариантную структуру экономического моделирования и не зависит от одной расчётной техники.

Domain adapters проверяют специальные дисциплинарные представления / расчёты и **не изменяют core-коды**.

[`ARTICLE1_FINANCIAL_ADAPTER_A.md`](ARTICLE1_FINANCIAL_ADAPTER_A.md) имеет статус **PROTOTYPE / OPTIONAL / NOT VALIDATED / OUTSIDE FROZEN CORE**.

# 5. Frozen CORE — 14 строк

| № | Объект | Когнитивная операция / вопрос | Ключевой наблюдаемый след | Базовые измерения* |
|---:|---|---|---|---|
| 1 | Уровень и граница системы | определить, какая система моделируется и на каком уровне; не переносить величины между системами без перехода | понятно, к какой системе относятся ключевые величины; переходы названы | Н, К |
| 2 | Ценность для пользователя / использующей системы | определить, чьё состояние / деятельность меняется и как; связать изменение с экономическим эффектом | пользователь и изменение его положения названы; механизм экономического эффекта показан | Н, И, О |
| 3 | Ресурсы и процессы | связать ресурсы с процессами, процессы — с экономическими величинами | видно, какой ресурс участвует в каком процессе и какие затраты / ограничения он порождает | Н, И |
| 4 | Различение экономических сущностей | не подменять одну сущность другой | выручка, прибыль, денежный поток, цена, ценность и др. употребляются в своих значениях | К, О |
| 5 | Временная размерность | различать запас / поток, момент / период, разовое / регулярное | величины имеют корректную временную размерность | К |
| 6 | Текущее состояние M0 | задать базу тех элементов, изменение которых затем заявляется | хотя бы для одного изменяемого элемента задано текущее состояние | Н, И, О |
| 7 | Механизм проектного изменения | связать действие проекта → элемент системы → изменяемую величину / состояние | прослеживается цепочка проектного воздействия | Н, И, О |
| 8 | Проектное приращение | отделить эффект проекта от продолжения системы без проекта | есть baseline или результат явно показан как дополнительный эффект | Н, К |
| 9 | Целевое состояние M1 | показать M1 сопоставимо с M0 там, где заявлено изменение; новые элементы вывести из проекта | изменения имеют базу; новые элементы имеют происхождение | Н, И, К, О |
| 10 | Временная последовательность | действие должно предшествовать приписываемому ему эффекту | даты действий и эффектов образуют допустимую последовательность | К |
| 11 | Финансирование / ресурсное обеспечение | связать потребность в ресурсе / капитале с источниками и условиями | понятно, откуда берётся ресурс и какие условия / обязательства возникают | Н, И |
| 12 | Предпосылки и риски | связать риск с предпосылкой / величиной модели | риск связан с тем, что именно может измениться | Н, И |
| 13 | Критерий решения | задать основание выбора и связать его с объектом, системой, временем и величинами | понятно, что оценивается, чем и как результат связан с решением | Н, И, К, О |
| 14 | Альтернатива | сравнить проект хотя бы с одним иным вариантом действия | назван иной вариант и при возможности сопоставлен по тому же критерию | Н, И |

\* `С` применяется сквозным правилом к любой релевантной строке.

# 6. Ключевые различения frozen core

## 6.1. Проектное приращение

Различаются:

1. состояние системы;
2. baseline «без проекта»;
3. проектируемое воздействие;
4. `Δ_project`;
5. целевое M1.

Рабочий вопрос:

> **что проект добавляет сверх того, что произошло бы и так?**

## 6.2. Критерий и альтернатива

Критерий = **по какому основанию выбираем?**

Альтернатива = **между какими вариантами действия выбираем?**

Ставка дисконтирования — параметр критерия, а не альтернатива. Сценарий внешней среды — не альтернатива действия.

## 6.3. Критерий: три слоя проверки

`семантика → онтология → расчётная прослеживаемость`

> **воспроизводимость расчёта ≠ экономическая корректность.**

# 9. Frozen rule

- менять строки, коды, пороги и определения;
- исправлять матрицу под новый артефакт;
- переписывать pre-analysis predictions;
