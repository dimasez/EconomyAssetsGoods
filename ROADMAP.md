# 1. North Star

Построить, теоретически обосновать и эмпирически проверить **архитектуру когнитивного обучения экономике**, а затем превратить её в научный корпус, образовательную методологию и систему интеллектуально требовательных учебных действий.

Главная формула:

> **Экономика — среда; модель — инструмент; мышление — результат.**

Рабочая траектория:

`реальность → различение → понятие → модель → система → измерение → решение → действие → обратная связь`

Принцип:

> **Сначала сущность и уровень системы — затем число и метрика.**

# 2. Каноническая системно-экономическая линия

`объект → ресурс → актив → конфигурация системы → способность системы → процесс → эффект → ценность`

Инженерный контур:

`требуемый эффект → функция → требуемая способность`

Операционный контур:

`фактическая способность → процесс → фактический эффект`

Ключевые различения:

- благо ≠ актив;
- ресурс ≠ актив;
- актив ≠ способность;
- способность ≠ процесс;
- процесс ≠ проект;
- продукт ≠ эффект ≠ ценность ≠ цена;
- метрика ≠ цель;
- критерий ≠ альтернатива;
- модель ≠ реальность.

# 3. Статья №1 — текущая постановка

Рабочее название v0.6:

> **«От категории к целостной экономической модели: архитектура когнитивных операций в экономическом образовании»**

Статья остаётся **теоретико-методологической с practice-informed pilot layer**. Практика используется как:

- источник исследовательской проблемы;
- поле операционализации;
- пилотный корпус артефактов;
- будущая база эмпирической проверки.

Практика **не** используется как доказательство причинного образовательного эффекта.

## Три интеллектуальных продукта статьи

### Продукт 1. Архитектура когнитивных операций

Теоретическая модель: какие операции и связи требуются предметной структурой экономических категорий, репрезентаций и моделей.

### Продукт 2. Протокол реконструкции

Метод перехода:

`семантико-онтологическая структура → обязательные различения → отношения → когнитивные операции → наблюдаемые следы / дефициты`.

### Продукт 3. Кодировочная матрица

Исследовательский инструмент: как обнаруживать в учебном продукте следы экономического моделирования и локализовать тип разрыва.

Полная конструкция:

`теория → протокол реконструкции → coding matrix → учебный продукт → профиль следов и дефицитов → проверка воспроизводимости`.

# 4. Целевая заявка о новизне

Не заявлять:

- новый общий instructional-design pipeline;
- «экономика впервые учит мыслить»;
- прямую психологическую реальность реконструированных операций;
- причинное формирование субъектности;
- новый чек-лист как самодостаточную научную новизну.

Рабочая зрелая версия:

> **Потенциальный вклад состоит в воспроизводимой процедуре перехода от структуры экономического содержания к наблюдаемым следам когнитивных операций в целостной экономической модели учебного проекта.**

Целевой **уровень новизны 2** означает:

- инструмент теоретически выведен;
- правила применения заданы явно;
- он различает работы и типы разрывов;
- независимые кодировщики получают приемлемо согласованные результаты;
- хотя бы одно заранее заданное предсказание проверяется на независимом материале.

Статус сейчас: **кандидат на уровень 2; ещё не доказано**.

# 5. Кодировочная матрица — текущий статус

Каноническая версия:

> **v0.7.2 — FROZEN FOR CORPUS A**

Файл: `ARTICLE1_CODING_MATRIX.md`.

## Что заморожено

На протяжении Corpus A не меняются:

- 14 строк core matrix;
- определения кодов `Н / И / О / К / С`;
- правила `0 / НД`;
- правила M0, механизма изменения, проектного приращения и M1;
- границы системы;
- временная размерность и последовательность;
- критерий и альтернатива;
- provenance;
- реестр противоречий;
- правило «соседство ≠ связь»;
- правило короткой проверки.

Новые сложности записываются только в **Issue Log**. Если правило не позволяет решить без догадки — `НД`.

## Что матрица кодирует

> **Предъявленную в артефакте экономическую модель, а не мышление учащегося.**

Наблюдаемый след совместим с выполнением операции, но не доказывает, кто и как её выполнил.

## Четыре свойства модели

- **целостность / интеграция** — можно ли пройти по явным связям;
- **корректность** — допустимы ли связи экономически;
- **согласованность** — не противоречат ли части продукта друг другу;
- **предъявленность основания** — показано ли в доступном источнике основание числа / утверждения.

Плюс отдельное измерение **наличия** элемента.

# 6. Архитектура CORE + adapters

Принято различение:

> **CORE coding matrix** — инвариантная структура экономического моделирования.  
> **Domain-specific adapters** — специальные правила проверки конкретных дисциплинарных техник.

CORE не должен зависеть от NPV, ROI, EBITDA, FCF или любой иной одной техники.

Критерий решения в core проверяется через:

1. объект;
2. систему;
3. смысл;
4. входящие величины;
5. время;
6. семантическую корректность;
7. расчётную прослеживаемость;
8. предъявленность предпосылок;
9. альтернативу.

Три слоя:

`семантика → онтология → расчётная прослеживаемость`.

Финансовый адаптер сохраняется только как **PROTOTYPE / OPTIONAL**, вне frozen core и без влияния на core-коды.

Шесть итоговых работ одного курса и одной образовательной архитектуры:

1. Sibergy;
2. «Белый банк» / Belobank;
3. Young Tourists;
4. Easy Stay;
5. FitBloom;
6. «Термоядерный синтез».

Все шесть работ строились по общей логике:

> **понять существующую систему → построить модель текущего состояния → спроектировать изменение → защитить решение.**

Различался акцент защиты, а не тип задания.

Sibergy использована как development / stress-test case. После freeze остальные пять работ используются для проверки различительной способности инструмента, а не для его подгонки.

- какие дефициты повторяются;
- какие строки требуют слишком большой интерпретации;
- как ведут себя уточнённые predictions;

# 13. Milestones

## Milestone A — Corpus A coded

Готово, когда все шесть работ имеют профиль по одной frozen версии.

## Milestone B — Cross-case discrimination established

Готово, когда понятно, какие строки и измерения реально различают работы, а какие дают floor / ceiling effects.

## Milestone C — Core revised if necessary

Готово, когда Issue Log рассмотрен только после полного Corpus A и принята v0.8 либо подтверждена v0.7.2.

## Milestone D — Cross-domain freeze

Готово, когда core выдерживает бизнес- и технологические проекты на уровне архитектуры, а доменные техники вынесены в adapters.

## Milestone E — Reproducibility test

Готово, когда независимые люди-кодировщики применили frozen инструмент к Corpus B и измерено межэкспертное согласие.

## Milestone F — Novelty level 2 test

Готово, когда воспроизводимость + различительная способность + заранее заданное предсказание выдержали независимый материал.

## Milestone G — Article revision

Только после этого полноценная следующая версия статьи получает эмпирически подкреплённый методический слой.

# 14. Место матрицы в статье №1

В основной текст **не входит полный manual**.

В статье нужны:

1. принцип наблюдаемого следа;
2. различение целостности / корректности / согласованности / предъявленности основания;
3. компактная пятиблочная карта матрицы;
4. один обезличенный mini-case Sibergy;
5. ссылка на полный research artifact / supplementary material.

Полная матрица не должна вытеснить предмет статьи и превратить её в текст о проверке школьных бизнес-планов.
